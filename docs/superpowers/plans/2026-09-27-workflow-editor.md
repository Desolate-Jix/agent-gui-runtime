# 可编辑工作流与局部试运行 / Editable workflows and local trials

**Goal / 目标：** 把已生成的学习图变成可读、可修改、能按修改后的语义重新执行的任务步骤；用户已于本轮认可评审方向并要求开发。

**Architecture / 架构：** 保留独立界面库、原始观测图与版本证据。在同一项目目录中保存引用确切项目快照的不可变步骤定义（编译产物，而非另一套界面图数据库）；步骤列表和步骤关系图读取同一份定义。试运行返回既有 Instant 命令，经原执行器现场定位；结果读取原落盘回执，人工/Agent 判定与输入派发事实分开。无第二执行器、无自动重放。

**Tech / 技术：** Python、现有短事务 MemoryWorkspace、PySide6 原生工作台、原 MCP/Instant 通道。版本号不改；不更新公开安装包。

## 已认可的范围 / Agreed scope

- 默认步骤视图，保留关系图与对应原图；独立界面仍可不属于流程。
- 可修改动作目标、输入绑定、步骤顺序、分支及条件，保存后执行建议必须来自修改后的定义。
- 工作流输入支持明确类型与必填检查；后续步骤可引用本次运行已验证的上游输出。局部运行缺上游值时明确指出，不能读取旧运行补齐。
- 自动生成的已观测步骤和人工编辑/推测步骤分开标记；人工审核状态与运行验证状态独立，不建立强制发布审批。
- 条件采用可判定的有限规则；图像/文本观察由 Agent 提供时标明判读来源，不冒充框架自动视觉验证。
- 局部试运行固定程序版本和起始步骤，一次一个待执行步骤；失败、不确定、缺数据时暂停，不重复派发；新版本不能继承旧版通过标记。

## 重点回归 / Review focus

1. 人工编辑一个步骤后，建议命令改变且历史观测证据不变。
2. 从中间开始却缺上游输出，执行前阻塞；不能借用另一次运行的值。
3. 未知回执/仍在运行的命令/失败派发不能记为通过，轮询不能重复派发。
4. 定义修改、分支修改或条件修改使新版验证待定，旧快照仍可读取。
5. 重复请求幂等、冲突保存拒绝；关闭/重开及异步旧响应不覆盖新编辑。

**Execution / 执行方式：** 主 Agent 负责设计、宿主接线、最终集成和实测；独立子任务只写约定文件，先只读盘点再有界移植/实现。按用户已给出的执行指令继续，不额外设置设计审批流程。
