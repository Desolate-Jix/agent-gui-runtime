# ArkPaint 结构保持40色映射设计

## 目标

直接修改并覆盖 `C:\Users\DesolateJix\Desktop\ArkPaint_v1.0.exe`，将现有逐像素最近色映射扩展为结构保持40色映射，使暗灰、暗红、深棕和蓝黑色块不再大量坍缩到 `1排1`，同时保证输出严格限定为游戏画板的40色。

## 已确认约束

- 用户已有现成备份，不创建额外备份，也不生成 `ArkPaint_v1.1.exe`。
- 最终交付路径保持为 `C:\Users\DesolateJix\Desktop\ArkPaint_v1.0.exe`。
- 保持现有 PySide6 界面、ADB连接、画布识别、调色板定位和绘制流程不变。
- 不修改最终发布、确认或其他高风险点击逻辑。
- 保留现有 `OKLab`、`CIE Lab`、`weighted_rgb` 和 `RGB` 映射，新增独立的结构保持模式，便于对照和回退。
- 40色表以游戏画板和当前 ArkPaint 色序为准；校验所有输出索引都位于 `[0, 39]`。

## 根因

当前算法独立地将每个像素匹配到距离最近的官方色。输入图中的多个暗灰、深棕和暗红虽然属于不同色块，但在稀疏的40色色板中可能拥有同一个最近邻 `1排1`。算法没有利用原始色块身份、亮度排序或相邻边界，因此不同结构被合并。

HTML 普通 PNG 保留了30余种非官方颜色，看起来层次丰富；HTML 拼豆图纸和 ArkPaint 最终都压缩为约12种官方色，并出现大量 `1排1`。因此修复点是公共颜色量化策略，而不是绘制点击层。

## 实现架构

### 1. 可重建程序包

从 PyInstaller EXE 中提取 `arkpaint` 字节码模块和运行资源。重建一个可重复打包的工作目录，保持原入口和除颜色处理外的模块行为。若 Python 3.13 字节码无法可靠反编译，不对机器码做盲目修改；改为保留可复用模块并以接口兼容的新颜色处理模块替换 `arkpaint.imaging.processing`。

### 2. 结构保持映射器

新增 `structure_preserving` 方法，处理过程为：

1. 将输入缩放、裁剪和颜色调整后的 RGB 图像作为唯一输入。
2. 对完全相同的源 RGB 建立稳定颜色簇；同一源色始终映射到同一官方色。
3. 为每个颜色簇计算像素数、感知亮度、OKLab 坐标、色相类别和与其他簇的接触边界权重。
4. 先按像素数和边界重要度排序，再从40色候选中选择总代价最低的颜色。
5. 总代价包含感知色差、亮度顺序破坏、相邻色块合并和过度复用惩罚。
6. 不强制全局一对一；只有在两个源簇确实足够接近时才允许共享官方色，避免为了增加颜色数而产生明显偏色。
7. 对透明像素沿用现有透明替换逻辑。

### 3. 代价函数

候选总代价采用确定性加权：

```text
cost = perceptual_distance
     + luminance_order_penalty
     + adjacent_merge_penalty
     + palette_reuse_penalty
```

- `perceptual_distance`：以 OKLab 欧氏距离为基础。
- `luminance_order_penalty`：防止明显不同亮度的源簇映射成同一亮度层。
- `adjacent_merge_penalty`：两个具有共享边界且源色差可见的色块不能轻易映射为同一官方色。
- `palette_reuse_penalty`：某官方色被多个差异明显的簇复用时逐步加罚。

权重作为模块常量保存，并由离线回归固定，首版不增加复杂调参界面。
