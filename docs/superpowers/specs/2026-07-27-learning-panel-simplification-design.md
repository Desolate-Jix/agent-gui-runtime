# 学习模式面板精简设计

## 目标

把当前开发面板从“历史实验入口集合”收敛成可理解、可审核、可继续执行验证的学习工作台。

核心用户路径：

1. 绑定目标软件并截图。
2. 运行完整学习流程。
3. 在三栏工作台审核界面路径、带框证据和 Agent 操作。
4. 人工修订错误框、结构和跳转。
5. 保存无执行授权的审核草稿。
6. 将审核草稿交给安全验证或执行模式。

Trace、原始 API 和历史实验生成器继续服务开发排错，但不占据普通学习流程。

## 设计原则

- 一个功能只保留一个主要入口。
- 学习模式不直接执行真实操作。
- 真实操作全部进入执行模式并重新截图、定位、Gate 和验证。
- Trace 保留底层证据，不在普通页面重复展示原始 JSON。
- 第一阶段移除 UI 入口，不立即删除仍可能被测试或 API 调用的后端能力。
- 第二阶段通过引用审计和回归测试后再删除死亡 JavaScript、废弃接口和翻译键。
- 不删除用户历史草稿、审核产物、CorrectionMemory 或 Agent Memory 数据。

## 页面结构

### 1. 学习界面

用途：完成从当前软件截图到人工审核草稿的完整流程。

保留：

- 应用和窗口选择。
- 绑定窗口与截图。
- 学习当前界面。
- 取消当前阶段。
- 九阶段进度与错误状态。
- 三栏审核工作台：
  - 左栏：以入口界面为中心扩散的“界面 -> 操作 -> 目标界面”拓扑图。
  - 中栏：`fused`、`numbered`、`source` 和人工修订图。
  - 右栏：界面属性、Agent 操作、目标控件、风险等级和规定跳转。
- 历史界面加入当前流程。
- 全图框编辑器。
- 保存审核草稿。
- 发布与执行验证交接。

从普通界面移除：

- SEEK 专用暂停任务交接。
- 模板界面/学习草稿界面的重复子切换。
- 草稿试跑和来源演示入口。
- 模型启动批准资料包。
- 校准预运行检查报告。
- PathGraph 集成就绪报告。
- 当前证据包。
- 精准理解候选图生成入口。
- Demo 串联包和 Demo 目标验收。
- 辅助模板审查包、接受建议、模拟接受、提升预检和审计请求预览。
- 重复的历史草稿长列表。
- 重复的截图/编号图区域。
- 旧学习草稿紧凑表单。
- 独立 CorrectionMemory 列表。
- 旧版大型页面 PathGraph 预览。
- 辅助模板审查清单。

迁移规则：

- SEEK 暂停任务交接从通用学习页面移出，保留为独立 Demo/开发入口。
- 原始生成器和诊断报告只允许从高级诊断或 Trace 使用。
- CorrectionMemory 状态通过保存结果和 Trace 查看，不在主页面持续铺开。

#### 左栏路径图

左栏必须是支持一对多跳转的点扩散拓扑图，不能使用纵向步骤列表模拟路径。

节点分为两类：

- 界面节点：一个可独立审核的界面、弹窗、抽屉或表单阶段。
- 操作节点：从某个界面出发的一条已审核操作，例如“查看详情”“打开筛选”“Quick Apply”。

连接关系固定为：

```text
界面节点 -> 操作节点 -> 目标界面节点
```

同一个界面可以连接多个操作节点，每个操作节点可以连接不同的目标界面：

```text
                 [查看详情] -> [详情界面]
[首页界面]  ->   [打开筛选] -> [筛选弹窗]
                 [Quick Apply] -> [申请表界面]
```

渲染数据继续来自 `single_application_workflow_review_v1`：

- 界面节点来自 `nodes`。
- 每条 `edge` 在视图中投影成一个操作节点。
- `edge.source_node_id` 决定操作从哪个界面发出。
- `edge.target_node_id` 决定操作连接哪个目标界面。
- 操作节点使用 `edge_id` 作为稳定选择标识，不另外保存一份路径数据。

布局和交互：

- 从 `workflow.entry_node_id` 向外分层扩散。
- 多个操作指向同一界面时复用同一个界面节点，不复制界面。
- 支持回环、自环和多级分支，不强制把图排成单向直线。
- 支持拖动画布、缩放和布局重置。
- 当前选中的界面节点和相邻操作高亮。
- 点击界面节点时，中栏切换到该界面的带框证据，右栏显示界面属性。
- 点击操作节点时，中栏保持来源界面的带框证据并高亮目标控件，右栏显示该操作的动作类型、目标控件、风险、前置条件、成功条件和目标界面。
- 尚未学习目标界面的操作连接到各自独立的 `needs_learning` 占位界面节点，不能把整个界面简化为单个“下一界面尚未加入”。
- 没有审核操作的界面显示“尚未添加操作”，但不伪造一条默认下一步。

路径图是审核视图：

- 不保存运行时点击点。
- 不授予 Execute 权限。
- 不从控件数量自动推断所有控件都会跳转。
- 只有已加入审核流程的操作才进入拓扑图。
- 每条操作仍必须拥有合法 `target_node_id`；未知目标通过独立占位界面表达，不放宽工作流校验。
- 新增或修改操作后，拓扑、中栏证据和右栏编辑器必须使用同一份内存状态立即刷新。

### 2. 模板展示

用途：查看已经人工批准的正式模板，不承担学习和执行。

保留：

- 加载正式模板。
- 界面路径图。
- 当前界面的页面详情。
- Agent 可用操作。
- 阻断条件、安全规则和验证规则。
- 缩放与布局重置。

移除：

- 加载模型产物。
- 加载软件 Profile。
- 加载 Agent Prompt。
- Prompt 比较、保存版本和回滚。
- 单独加载界面地图和校准报告。
- 填写检查、回归检查和样本检查。
- 执行下一步。
- 默认显示的 API 原始响应。

Prompt 和模型配置继续由设置/开发工具管理，不属于模板查看。

### 3. Trace 审计

用途：排查学习、审核、定位、Gate 和执行验证失败。

保留：

- Trace 列表和刷新。
- 阶段流程。
- 原始请求与响应。
- 截图、overlay、模型原文和解析错误证据。
- 打开本地证据文件。

Trace 是开发诊断界面，不要求普通用户理解所有字段。

### 4. 路径图安全验证

用途：验证审核后的路径在当前截图上是否仍可定位并通过 Gate。

保留：

- 加载审核路径。
- 生成验证计划。
- Dry-run 下一步。
- Gate 结果。
- 后置验证计划和时间线。
- 当前路径图和页面详情。

移除或迁移：

- “执行下一条安全动作”迁移到执行模式。
- API 原始响应迁移到 Trace。
- 重复的路径编辑、保存和复制入口由三栏审核工作台负责。

## 数据流

```text
绑定/截图
  -> 学习工作流
  -> 学习草稿
  -> 三栏人工审核
  -> 保存 reviewed workflow candidate
  -> 路径图安全验证（dry-run）
  -> 显式发布 Agent Memory
  -> 执行模式重新截图与执行验证
```

学习界面只写审核候选，不生成点击授权。路径图安全验证只做 dry-run。执行模式不得复用历史点击点。

## 删除策略

### 阶段一：界面收敛

- 删除普通页面中的重复 DOM 区块和入口。
- 保留底层 API、Trace 和测试夹具。
- 清理对应布局 CSS，避免隐藏区继续占空间。
- 保留临时兼容 ID 仅限仍有调用者的元素。

### 阶段二：死亡代码清理

- 使用代码引用、事件绑定和路由测试确认无调用者。
- 删除仅服务已移除 UI 的 JavaScript handler。
- 删除无调用者 API、翻译键和 CSS。
- 每组删除后运行最窄相关测试和完整面板回归。

阶段二不得删除 Trace 解析、学习工作流、人工框编辑、审核保存、Agent Memory 或 Gate API。

## 错误处理

- 学习失败必须显示失败阶段和 Trace 入口。
- 草稿缺图、校验和不匹配或来源失效时保持 safe-stop。
- 保存失败不得关闭编辑器或伪装成功。
- 发布失败保留已保存审核草稿。
- 被移除的旧入口不自动调用替代行为，避免隐藏错误。

## 验收标准

### 学习界面

- 首屏只显示绑定/截图、学习按钮和进度。
- 学习完成后直接进入三栏审核工作台。
- 普通学习页面主要命令不超过约 12 个。
- 不再出现 SEEK 专用文案、报告生成器或辅助模板实验按钮。
- 框编辑保存后，中栏证据与路径节点立即刷新。
- 左栏使用“界面 -> 操作 -> 目标界面”点扩散拓扑，不使用纵向步骤列表。
- 一个界面的多个操作必须能同时连接到多个目标界面。
- 点击界面节点必须切换对应带框证据；点击操作节点必须显示其目标控件和跳转编辑项。
- 多条操作指向同一目标时不得复制目标界面节点。
- 尚未学习目标的操作必须分别连接独立占位界面，不能合并成一个默认“下一界面”。

### 模板展示

- 只显示模板结构、页面详情、操作和安全规则。
- 不显示模型、Prompt、校准和执行工具。

### Trace

- 原有 Trace 内容仍可访问。

### 路径图安全验证

- 只允许生成计划和 dry-run。
- 不存在真实执行按钮。

### 安全

- 学习和模板页面没有 live click、live fill 或 submit 入口。
- final submit、send、confirm、payment 和 delete 继续被硬阻断。

## 测试计划

- 静态面板结构测试：保留控件存在，被移除控件不存在。
- JavaScript 事件绑定测试：不得绑定不存在的旧 DOM。
- 学习流程回归：绑定、截图、完整阶段链和取消。
- 三栏审核回归：节点选择、证据切换、框编辑、操作和跳转保存。
- 路径拓扑回归：一对多分支、共享目标、回环、自环和独立占位目标。
- 路径交互回归：点击界面切图、点击操作高亮控件并打开对应编辑状态。
- 模板展示回归：加载与只读渲染。
- Trace 回归：刷新和证据读取。
- 安全验证回归：dry-run 强制开启，真实执行入口不存在。
- 浏览器视觉检查：1280px 和 1920px，确认无重复区块、无横向溢出。

## 非目标

- 本轮不重新设计执行模式。
- 不提高模型识别率。
- 不修改 Stage1、Stage2、VISTA、OCR、rerank 或 Gate。
- 不删除历史学习产物。
- 不把 SEEK 逻辑改造成通用识别规则。
