# 单软件通用流程学习与人工审核设计

## 目标

第一版只处理一个目标软件和一个目标窗口。Agent 根据自然语言目标连续探索界面，自动形成候选流程图；用户集中审核、修正并显式发布为 Agent Memory；执行模式随后重新截图、重新定位并经过 Gate 验证流程是否可复用。

SEEK 只是验证案例，不能定义数据结构、界面名称或流程步骤。

## 核心对象

学习产物的主对象是 `SingleApplicationWorkflowDraft`，而不是单张截图、单个网站模板或按时间排列的 JSON 列表。

```text
学习目标
  ↓
界面状态 A ──操作/验证──> 界面状态 B ──操作/验证──> 界面状态 C
  ↓                         ↓                         ↓
截图、带框图、结构          截图、带框图、结构          截图、带框图、结构
  ↓
人工审核版本
  ↓
显式发布
  ↓
Reviewed Workflow Memory
  ↓
执行模式重新定位、Gate 与结果验证
```

## 自动生成规则

1. Agent 连续操作时，界面状态发生显著变化便生成候选节点。
2. 执行动作形成候选边。
3. 重复界面通过状态签名复用同一节点，不按截图次数生成重复节点。
4. 学习过程不中断等待逐节点批准。
5. 流程完成或安全停止后，用户集中审核。
6. 未学习、证据缺失或失败节点必须显示真实状态，不得借用上一个节点的内容。

## 开发面板

开发面板围绕四个问题组织：

1. 识别了哪些界面？
2. 每个界面的框和结构是否正确？
3. 哪一步失败？
4. 修订后能否发布并被执行模式复用？

### 主布局

```text
┌ 学习目标 | 目标软件 | 当前状态 | 开始/继续学习 ┐
├───────────────────────────────────────────┤
│ 通用流程 PathGraph                         │
├────────────────────┬──────────────────────┤
│ 当前节点带框图      │ 当前节点结构与操作    │
│ 原图/编号/融合/修订 │ 错误、缺失、审核状态  │
├────────────────────┴──────────────────────┤
│ 修改 | 批准节点 | 重识别 | 发布 | 执行验证 │
└───────────────────────────────────────────┘
```

点击 PathGraph 节点时必须原子更新：

- 当前节点带框图；
- 页面详情；
- 区域、控件和操作关系；
- 进入与离开条件；
- 人工修改记录；
- Memory 发布状态；
- 执行验证结果。

切换节点时先清空上一节点内容。加载失败时显示 `未学习`、`证据缺失` 或具体错误，不得残留上一节点数据。

### 高级诊断

以下内容默认折叠，按当前节点和阶段打开：

- Trace；
- 原始 JSON；
- 文件路径和 checksum；
- OCR、UIA、视觉候选；
- 模型配置和原始输出；
- benchmark、fixture 和 scaffold；
- 暂停任务交接与进程控制；
- 内部 contract 与 Gate 评分。

## 用户面板

用户面板展示“我教过 Agent 的工作”：

- 新建流程学习；
- 描述目标；
- 查看 Agent 探索进度；
- 集中审核流程图；
- 修改错误界面；
- 保存审核草稿；
- 显式发布为可重复任务；
- 运行任务；
- 界面变化时只审核变化节点。

用户面板不展示 OCR、VISTA、rerank、模型参数、文件路径或原始 JSON。

开发面板和用户面板共享：

- `InterfacePathGraph`
- `InterfaceEvidenceViewer`
- `InterfaceReviewEditor`

开发面板额外提供 Trace、阶段重跑和诊断。

## 人工修改范围

### 流程结构

- 重命名节点；
- 删除错误节点；
- 合并重复节点；
- 从已有捕获补充遗漏节点；
- 调整开始、结束和阻塞节点；
- 新增、删除和重新连接边；
- 修改操作后的目标界面。

### 识别框

- 添加、删除、移动和缩放；
- 合并图标、文字和背景为完整控件；
- 拆分错误大框；
- 标记遗漏区域；
- 标记装饰或忽略区域；
- 撤销和重做；
- 对比原始与修订结果。

### 界面结构

- 名称；
- 控件类型；
- 所属区域；
- 父级容器；
- 是否可操作；
- 是否只读；
- 是否为重复项目；
- 是否敏感或危险。

父子关系通过选择或拖放修改，不要求用户编辑内部 ID。

### 操作

- 点击、输入、选择、滚动、打开详情、返回、切换标签、读取、打开流程和等待；
- 删除错误操作；
- 重新绑定目标；
- 修改操作名称；
- 标记执行时重新定位；
- 标记需要人工确认。

### 转换与验证

- 来源和目标节点；
- 前置条件；
- 成功条件；
- 失败条件；
- 超时行为；
- 弹窗、登录和阻塞处理。

### 安全

用户可以增加限制，但不能关闭硬 Gate。最终提交、发送、删除、确认和付款等危险动作继续由系统安全策略控制。

## 保存、发布与负反馈

1. 所有修改先保存为审核草稿。
2. 保存后，流程图、带框图和页面详情必须立即刷新。
3. 只有显式“发布流程”才写入 Reviewed Workflow Memory。
4. 每次修改同时写入 Correction Memory 候选。
5. Correction Memory 只有经过跨样本验证和人工批准后才能成为通用规则。
6. 发布生成新版本，保留来源、差异、审核人和回滚信息。

## 执行验证

发布后必须通过执行模式做受控验证：

- 重新捕获目标窗口；
- 重新识别目标控件；
- 检查候选新鲜度；
- 通过 Gate；
- 每次只执行一步；
- 验证目标界面或结果；
- 危险动作安全停止。

人工框不构成点击授权，旧坐标不得直接复用。

## 第一版范围

第一版实现：

- 单软件、单窗口；
- 一条主要路径；
- 自动候选节点和边；
- 节点点击联动证据；
- 框、结构、操作和转换编辑；
- 审核草稿；
- 显式发布 Memory；
- 执行模式逐步验证；
- Trace 按需打开。

暂不实现：

- 跨软件流程；
- 多用户协作；
- 云同步；
- 自动升级 Correction Memory；
- 复杂并行分支；
- 无限制运行时自动执行。

## 验收

1. 一个非 SEEK 软件可以从目标描述生成至少两个界面节点和一条转换边。
2. 点击任意节点能看到该节点自己的带框图、页面详情和操作关系。
3. 节点切换时不存在上一节点残留。
4. 用户能修改框、结构、操作和边，并立即看到刷新结果。
5. 未发布修改不会影响正式 Memory。
6. 发布后执行模式能重新定位并逐步验证至少一条低风险边。
7. 最终提交、发送、删除、确认和付款没有被授权。
8. Trace 能从当前节点和当前阶段按需打开。
