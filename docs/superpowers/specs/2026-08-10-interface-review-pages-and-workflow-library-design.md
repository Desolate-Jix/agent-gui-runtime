# 单界面审核大页与独立软件流程库设计

## 目标

把当前学习面板中混合显示的“未审核界面、已审核界面、软件流程、证据预览和加入流程”拆成三个清晰的顶级工作区：

1. 未审核界面；
2. 已审核界面；
3. 软件流程。

审核状态与流程归属是两个互相独立的维度。未审核和已审核单界面都允许加入流程，但未审核界面不得进入 Agent 可操作证据上下文。

## 核心原则

- 单界面资产只保存一份；审核页只是同一资产库的状态投影。
- 软件流程只引用单界面资产，不复制截图、框或 Agent 证据。
- 加入流程不代表 Agent 获得使用资格。
- 只有人工审核、版本未过期且证据契约有效的单界面才能标记为 `agent_usable=true`。
- 修改已审核界面的框、描述、动作或跳转后，必须自动回到未审核状态。
- 未审核节点可以参与路径设计，但 Agent 只能收到阻断信息，不能收到可执行控件和历史坐标。
- 即使界面已经审核，真实操作仍必须使用当前截图重新定位，并经过 Gate 和操作后验证。
- Workflow / PathGraph 是可复用资产，不是执行授权。

## 顶级信息架构

学习成果区使用三个顶级页签：

```text
[ 未审核界面 N ] [ 已审核界面 N ] [ 软件流程 N ]
```

不再同时并排渲染已审核和未审核列表，也不再把“选择单界面、加入流程、路径图和证据”纵向堆在同一个长页面中。

## 未审核界面页

未审核页使用左侧资产列表和右侧证据工作区：

```text
┌──────────────────────────────────────────────┐
│ 软件筛选  界面类型筛选  搜索  未审核数量     │
├──────────────┬───────────────────────────────┤
│ 单界面列表   │ 当前界面证据                  │
│              │ ├─ 状态和来源                 │
│ 按软件分组   │ ├─ 带框截图                   │
│ 缩略图       │ ├─ Agent 可读摘要             │
│ 名称         │ ├─ 控件、动作和跳转           │
│ 流程标签     │ └─ 修正/改名/加入流程/审核    │
└──────────────┴───────────────────────────────┘
```

允许操作：预览、修正、改名、打开源文件夹、加入流程、审核通过。加入流程时明确提示该节点只能用于流程设计，Agent 暂不可用。

## 已审核界面页

已审核页复用同一套布局和证据预览组件，只改变数据过滤和操作集合。

允许操作：预览、加入流程、打开所在流程、重新修正、归档。重新修正会撤销当前审核版本，并把资产移动回未审核页。

## 软件流程页

软件流程是独立页面，不归属于任何审核页：

```text
┌──────────────────────────────────────────────┐
│ 软件选择  流程选择  新建  改名  打开文件夹  │
├──────────────────────────────────────────────┤
│                  路径图                      │
│           点击节点切换下方证据               │
├──────────────────────────────────────────────┤
│ 当前节点带框截图 70% │ Agent 证据与跳转 30% │
└──────────────────────────────────────────────┘
```

图中始终保留其他节点。点击节点只改变选中状态和下方证据，不隐藏其余节点。右键节点继续使用现有连接弹窗和证据图控件选择器。

## 加入流程

未审核页和已审核页共用“加入流程”弹窗：

```text
目标流程：     [流程选择]
加入方式：     [仅加入节点 / 加入并连接]
来源界面：     [已有流程节点]
来源操作：     [在证据图中选择控件]
目标界面：     [当前单界面]
验证方式：     [界面身份或结构变化]
```

加入成功后切换到软件流程页，居中新加入节点。仅加入节点时保持未连接状态；连接逻辑继续通过路径图和连接弹窗完成。

## 状态视觉语义

- 绿色填充：已审核且 Agent 可读；
- 橙色填充：未审核，Agent 不可用；
- 红色填充：证据无效、来源缺失或版本过期；
- 蓝色外圈：当前选中；
- 灰色虚线边：未连接节点；
- 橙色虚线箭头：路径经过未审核节点。

状态颜色、选择状态和连接状态不得复用同一种视觉编码。

## 数据契约

### 单界面资产

```json
{
  "interface_id": "job_detail",
  "display_name": "岗位详情",
  "application_identity_key": "website:example.com",
  "review_status": "human_approved",
  "reviewed_by_human": true,
  "evidence_revision": 7,
  "reviewed_revision": 7,
  "agent_usable": true,
  "agent_eligibility_reason": "human_reviewed_current_revision"
}
```

`agent_usable` 必须由后端根据审核状态、证据版本和契约完整性计算，不能由面板直接设置。

### 流程节点引用

```json
{
  "node_id": "node_job_detail",
  "interface_id": "job_detail",
  "referenced_revision": 7,
  "required_for_route": true
}
```

流程节点不复制单界面证据。面板读取流程时，通过 `interface_id` 投影当前审核状态和证据版本。

## Agent 使用门控

Agent 上下文只允许投影满足以下条件的节点：

```text
review_status 属于人工审核状态
AND reviewed_by_human = true
AND evidence_revision = reviewed_revision
AND evidence_contract_valid = true
```

不满足条件时只返回阻断元数据：

```json
{
  "interface_id": "apply_form",
  "availability": "blocked_unreviewed_interface",
  "agent_usable": false,
  "required_action": "human_review"
}
```

不得返回该节点的可操作控件、点击点或历史坐标。包含未审核必要节点的流程可以保存，但不能标记为 `agent_ready`。

## 异常与版本行为

- 未知审核状态按未审核处理。
- 来源截图或证据文件缺失时标为无效，不静默回退为已审核。
- 修改已审核资产时增加证据版本并撤销审核资格。
- 流程引用旧版本时显示版本过期，不继续投影旧证据给 Agent。
- 删除仍被流程引用的资产时优先归档并展示引用关系，不直接破坏流程文件。

## 验收标准

1. 未审核和已审核显示为两个可切换的大页，而不是并排小栏。
2. 软件流程是独立大页，路径图和当前节点证据同时可见。
3. 两种审核状态的单界面都能加入流程。
4. 未审核节点在流程中使用橙色标识，并且不能进入 Agent 可操作上下文。
5. 已审核节点修改后自动回到未审核状态。
6. 同一个单界面加入多个流程时不复制证据资产。
7. 点击路径图节点只切换证据，不隐藏其他节点。
8. 所有真实操作仍要求当前截图、重新定位、Gate 和操作后验证。
