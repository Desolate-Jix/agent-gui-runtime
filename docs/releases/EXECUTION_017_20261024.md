## English

Execution 0.1.7 adds an explicit **Use the current Agent** entry:
`execution_client.py --current-agent`. The connected main Agent reads Runtime
images, locates targets and judges results; Runtime preserves evidence binding,
input authorization, window/freshness checks, one-shot dispatch and receipts.
The supported managed loop is basic clicking. It does not need a separate
Runtime visual or Decision API, local model weights or a visual subagent;
hosting-client model service and quota still apply.

The persistent adapter owns the original command, fresh capture and control
request identities. Resolve alone does not click; explicit continue resumes
the same command. Pending/unknown receipts are read without replay. Actual
after-image binding is required for caller success/failure judgments following
input; uncertainty keeps new input blocked. Cancel and completion have distinct
states and cleanup is verified independently. A cancellation receipt identity
bug in the shared client is fixed without loosening server gates.

The local MCP configuration generator also accepts `--current-agent`, isolates
an inherited Decision profile and preserves old explicit API/local/delegate
routes. Capabilities default to unknown and never grant input. Conflicting
model settings and administrator mode are rejected for the new adapter.
The published API workflow and Amadeus extension remain available.

Source acceptance completed 20 fresh-evidence navigation steps in one 7-Zip
session, plus evidence/uncertainty/completion negative controls and cancellation
while awaiting grounding. The affected offline suite passed 368 cases before
the release-version update. Exact final installation and package facts are
recorded in the linked acceptance and release asset reports, not inferred from
source checks. [Evidence and limits](../verification/CURRENT_AGENT_LIVE_20261024.md).

The installed 0.1.7 candidate completed five Calculator clicks ending at
`1 + 2 = 3`, then passed after-action cancellation and an independent
awaiting-grounding cancellation. All **684 installed payload hashes** matched
before/after; both clients/hosts cleaned up and native check-uninstall removed
the owned temporary installation. The final documentation rebuild preserves
the candidate's **583 Python files** and all production/configuration bytes;
it is not an additional GUI run. Final affected component checks passed 10
cases; client/HTTP checks passed 116 plus the separately enabled external-client
case, and unchanged extension checks passed two. Overlapping suites are not
added. The installer is unsigned; clean-machine dependency setup and normal
OS shortcut/registry integration were not newly accepted.

### Amadeus and future updates

The resource-only HTTP extension remains **0.0.4**, with the unchanged wheel
from the [0.1.6 release](https://github.com/Desolate-Jix/agent-gui-runtime/releases/tag/instant-v0.1.6).
It connects to an independently installed Runtime. Compatible Runtime patches
do not require a different wheel. A changed Skill/manifest or incompatible Host
contract still needs its own reviewed extension version.

This CLI adapter is not a new managed HTTP tool or a newly accepted Pi
current-Agent route. The existing 0.0.4 Skill describes its existing API/review
workflow. Runtime release and Amadeus store approval remain separate.

Automatic update checking, trusted downloads, installation-wide task guards and
rollback are documented proposals, **not implemented or enabled features** of
0.1.7. See the [Runtime strategy](../development/RUNTIME_UPDATE_STRATEGY.md) and
[Amadeus strategy](../development/AMADEUS_UPDATE_STRATEGY.md).

## 简体中文

执行版 0.1.7 新增明确的“使用当前 Agent”入口
`execution_client.py --current-agent`：当前主 Agent 实际读取 Runtime 原图、定位、
核验结果；Runtime 保留证据绑定、输入授权、窗口与新鲜度检查、单次派发和回执。
首版受管理的输入范围是基础点击闭环，无需独立 Runtime 视觉或 Decision API、
本地权重或视觉子 Agent，仍使用承载客户端的模型服务与额度。

新适配层保持同一连接，关联原命令、每次新截图及后续控制请求。resolve 本身不点击，
单独 continue 才继续原命令；pending/未知结果只读回，不重放。输入后的成功／失败
判断必须绑定真实后图，不确定时禁止新输入。取消、完成和清理分别核对；同时修复
共享客户端把取消控制请求误当原 worker 身份的问题，不放宽服务端门禁。

MCP 配置生成器新增同名选择，并隔离父环境遗留 Decision 配置。原有明确的 API、
本地与委派路线保留；能力默认未知，声明能力不等于输入授权。新封装在连接前拒绝
冲突的模型配置与管理员模式。原 API 工作流和 Amadeus 扩展仍可使用。

源码实测在同一 7-Zip 会话完成 20 步新图导航，以及错图、不确定结果、完成封锁和
等待定位时取消的负控检查。发行版本更新前的相关离线套件 368 项通过。确切安装
载荷、安装态实测和清理结果以[本轮验收](../verification/CURRENT_AGENT_LIVE_20261024.md)
及发布附件为准，源码通过不转计安装态通过；不新增速度、通用成功率或 token 节省结论。

0.1.7 安装候选完成计算器五次点击，结果为 `1 + 2 = 3`，随后通过动作后取消及
另一会话的等待定位取消；**684 项安装载荷摘要**在运行前后完全一致。两个客户端／
宿主正常清理，原生 check-uninstall 删除了本轮临时安装。最终仅重包文档，**583 个
Python 文件**及其余生产／配置字节保持候选一致，不算新增桌面实测。最终相关组件
检查 10 项通过；客户端／HTTP 116 项及单独启用的外部客户端 1 项通过，未改扩展
检查 2 项通过，重叠分组不累加。安装器未签名，本轮未新增全新机器依赖安装或正常
快捷方式／注册表集成验收。

Amadeus 的资源型 HTTP 扩展保持 **0.0.4**，保留 0.1.6 发布中的原 wheel 字节和
固定下载链接。Runtime 独立安装，协议兼容的修复无需每次重装 wheel；Skill／声明
实际变化或 Host 合同不兼容时，才发布并审核新的扩展版本。本轮 CLI 封装不等于
已新增受管 HTTP 工具或已验收 Pi 当前 Agent 路线，0.0.4 的 Skill 保持原 API／审核
工作流。Runtime 发布与商店批准仍分开。

自动检查、可信下载、安装级活动任务保护和可靠回滚目前仅为后续方案，**0.1.7 没有
实现或启用自动更新**。见 [Runtime 更新方案](../development/RUNTIME_UPDATE_STRATEGY.md)
