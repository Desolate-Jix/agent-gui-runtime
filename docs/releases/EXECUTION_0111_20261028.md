# Execution 0.1.11 — release proven never-started HTTP owners

Date / 日期：2026-10-28 (Pacific/Auckland)

Runtime target / Runtime 目标：`instant-v0.1.11`

Connector target / 连接器目标：`amadeus-extension-v0.0.8`

## English

0.1.11 addresses the never-started-owner failure reported in
[connector review #11](https://github.com/Code-Amadeus/Amadeus-Extensions/pull/11#issuecomment-6438014289).
Initializing an HTTP MCP owner before calling `instant_start` leaves the Runtime
in its initial state with `cleanup_verified=false`. That flag describes absent
cleanup evidence; it does not mean a host was started. Earlier code rejected
DELETE of this otherwise unused owner and could block another Work.

DELETE now has a narrow alternative to the existing cleanup-verified route:
explicit lifecycle evidence must establish that this Runtime instance never
attempted startup or attachment, holds no execution resources and has no pending work. Initial-looking
status, `host_alive=false` or a missing process alone is insufficient. A start
attempt remains an attempt even if it fails or returns to an initial-looking
state; it cannot acquire never-started proof by changing those status fields.

The normal `cleanup_verified=true` release route remains. Started, active,
unknown or unclean sessions still require the existing original-session cleanup
and settlement checks. This change releases an unused HTTP transport owner; it
does not create a host, execute input, complete a task or transfer an old
workflow. Do not start/stop Runtime or invoke recovery merely to make an unused
owner releasable. Server-side proof is required; clients cannot supply it by
asserting an initial state.

0.1.10's proven rejected-control and bound-observation settlement remains in
place. `recover` and `resume_pre_dispatch` settlement remains unqualified.
Disconnected `instant_recovery_preview` / `instant_recover_session` use remains
operator-only; Pi must not take over an old workflow. Main's bound-image review
and explicit continuation within the same live session retain their contracts.
No model/provider default, threshold or input authorization is changed.

Connector 0.0.8 updates its packaged Runtime recommendation and bilingual
guidance. Connection settings, permissions, contributions and the minimum
HTTP/pre-action protocol contract of 0.1.6 remain unchanged. That minimum does
not certify all later patches, and historical 0.0.4/0.1.6 installed Pi evidence
does not validate the new 0.0.8/0.1.11 combination. Runtime and connector are
installed and published separately; independent catalog acceptance remains
maintainer-owned.

## 简体中文

0.1.11 处理[连接器审核 #11](https://github.com/Code-Amadeus/Amadeus-Extensions/pull/11#issuecomment-6438014289)
报告的未启动所有者释放失败。HTTP MCP 所有者初始化后、尚未调用 `instant_start`
时，Runtime 保持初始状态，`cleanup_verified=false` 表示没有清理证明，并不表示
已经启动宿主。旧代码拒绝 DELETE 这个未使用 owner，可能阻塞其他 Work。

DELETE 现在为原清理已核验路线增加一个严格例外：明确生命周期证据必须证明本实例
从未尝试启动或附着、未持有执行资源且无待处理工作。看似初始的状态、`host_alive=false`
或进程不存在本身均不足以放行。失败的启动也是启动尝试；即使状态回到看似初始，
也不能通过修改状态字段取得“从未启动”的证明。

原 `cleanup_verified=true` 释放路线保留。已启动、活动、未知或未清理会话仍须
遵守原会话的清理与结算检查。这只释放未使用的 HTTP 传输所有者，不创建宿主、
不执行输入、不结算任务，也不转移旧工作流。不要仅为使未使用 owner 可释放而
启动／停止 Runtime 或调用恢复。证明由服务端核验，客户端声明初始状态不能代替。

0.1.10 的有证明拒绝控制和绑定观察结算继续保留；`recover`、
`resume_pre_dispatch` 结算仍未认证。断线后的 `instant_recovery_preview`／
`instant_recover_session` 仍仅限操作员，Pi 不得接管旧工作流；同一活动会话中
Main 看绑定原图后明确继续原任务的合同保留。不改模型／服务商默认值、阈值或
输入授权。

连接器 0.0.8 更新包内 Runtime 推荐和双语说明，连接设置、权限、贡献声明以及
0.1.6 的最低 HTTP／输入前审核协议合同不变。最低协议不证明所有后续补丁兼容；
历史 0.0.4／0.1.6 安装态 Pi 证据不验证 0.0.8／0.1.11 新组合。Runtime 和连接器
分别安装、分别发布，独立商店验收继续由维护者处理。
