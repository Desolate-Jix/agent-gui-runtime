---
name: gui-execution
description: Execute an explicitly authorized Windows GUI task through the connected AgentGUI Runtime MCP, preserve original request and evidence identities, handle review without replaying input, and close owned windows and the Runtime session.
---

Read `references/runtime.md` before using the connected Runtime. Discover its actual tools and current schemas; Pi tool names may be namespaced or hashed, so never invent a tool name. This Skill supplies no tools, authority, executor, learning mode or shell route.

Keep one Runtime MCP connection throughout the complete authorized Work task. The operator starts the authenticated loopback HTTP MCP daemon independently; this extension never launches Python, chooses executable paths, supplies model API keys or changes profiles. Confirm the operator's task scope and Runtime local-input setting; one input owner at a time. Start the execution host once, wait for ready, launch/select the intended window, use current bound observations, submit the actual task, and settle original receipts. A successful launch or asynchronous acknowledgement is not task success.

For pending, unknown, timeout, interrupted input or unavailable images, keep the original request/run/command IDs and inspect their state. Never use a new ID to replay possibly executed input. Discover the running Runtime's actual tools and reported version; HTTP and pre-action Main review are not provided by the frozen 0.1.5 installer. At a real `pre_action_review_packet.v1` or `field_review_packet.v1`, request `agent_command_status` with `command_id=packet.execution_request_id` under a new outer request ID, then retrieve that status request's bound image with `instant_image`; the original execution is still pending. Use `view=before` for a pre-action candidate and `view=after` for a field result. Compare the original task target with the marked candidate/point for pre-action review; compare the already-entered text for field review. Inspect the exact bound evidence, copy `caller_controls.review.request` and add only the actual verdict/reason, then separately use the returned continue recipe. Review alone performs no input. Pre-action continuation keeps the original job/candidate and must pass fresh target-region and existing hard gates before one dispatch; field continuation does not retype and any submit suffix still uses normal gates and verification. If the service supplies no resumable ticket or the current candidate becomes stale, stop and report it. A handoff or version number is not a ticket. Do not manufacture hashes, wait IDs, success or a restart/replay.

Close only windows launched by this task using the returned launch handle/process identity. Resolve owned save dialogs only when that specific choice is authorized. Verify `window_closed` before `instant_stop`, then poll `instant_status` until the host is down, pending IDs are empty and cleanup is verified. Only then release the native HTTP MCP session so a new Work can acquire ownership. A network disconnect does not cancel input or prove cleanup. Do not repeatedly reconnect, restart the daemon or steal an active owner to hide an uncertain result. Report task outcome separately from cleanup. Disabling the extension does not stop the independently started service.

中文要点：仅执行当前明确授权的任务；保持同一连接和原始 ID；未知输入绝不重放。前置候选审核看 before 原图与原候选，文字结果审核看 after 原图；均使用真实 review→单独 continue，审核本身不输入。前置继续仍须新鲜度和输入门禁通过，不能强行沿用变化的目标；无票据就停报。只关闭本轮自有窗口并验证，再停止与确认宿主清理。不要使用学习、shell 绕行或删除浏览器资料。
